# 用户流程与恢复说明

安装向导的用户操作：

1. 原厂系统获得 root；
2. 上传并运行对应机型的安装程序（`<机型>-installer`）；
3. 页面生成并下载备份 ZIP（BL2、FIP、原厂首块、板级数据），核对页面
   信息并输入 `yes`；
4. 自动进入 Web U-Boot（本项目默认 `http://192.168.1.1/`，已有环境变量可能改变地址）；
5. 选中同一 ZIP，点击"初始化并恢复"；
6. 上传 sysupgrade。写入后设备尝试启动系统；网页不知道新系统的 IP，可能持续显示等待。

无法自动确认设备时，原厂端仅提供“全部可见 MTD 分区”tar 归档下载。归档由设备边读边传输，不需要把整片 Flash 放入内存；其中含 `partitions.json` 和每个 `mtdN.bin`。MTD 分区可能相互重叠，也可能未覆盖整片芯片，因此此归档不标称为整片 ROM 镜像。若下载中断，应丢弃不完整文件并重新下载。

## 关键风险（沿用原版，未做底层改造）

- **初始化 UBI 到 FIP 重写完成期间请勿断电。** 若在"初始化成功但尚未写
  FIP"时断电，设备可能再也进不了 Web 页面。页面在执行 `ubi-rebuild`
  前会明确提示。
- 原厂端 BL2 写入中断电也可能不可免拆恢复。
- 后续断电只保证**已写入且再次读取校验成功的步骤**能被向导识别；UBI
  初始化窗口不可续传。
- 备份 ZIP 和 MTD 归档都不是逐位恢复镜像：原厂 MTD 备份不含 NAND OOB/坏块标记；源
  分区有坏块时自动刷写流程会退出，只显示 MTD 归档下载入口。
- **机型匹配不等于设备唯一身份匹配**：同型号另一台机器的 ZIP 无法仅凭
  当前上游接口可靠识别。页面会展示备份包内原厂可读标识并让用户确认
  "这份备份来自本机"；不自动导入其他机器的 PON 数据。

## 恢复状态（Web U-Boot 页）

| 观察到的状态 | 页面动作 |
| --- | --- |
| 当前任务仍在运行 | 显示 `/api/task` 进度，禁止新的上传/写入 |
| 没有完成标记、只有临时 `fip`，缺 `ubootenv`/目标卷 | 要求上传 ZIP；确认后重建 |
| 基础卷已创建但没有完成标记 | 要求重新选 ZIP；读现有 FIP/板级卷并与 ZIP
比较，只补写不匹配项；默认不再次重建 |
| `wizard_done=1` 且哈希匹配 | 直接显示 sysupgrade；读取或校验失败时要求
重新上传 ZIP |
| 已有 `fit` 卷 | 保留再次 sysupgrade 入口 |

## 防误操作 vs 安全认证

设备端 FIP 校验只验证结构，机型核对发生在向导层。页面提示属于防误操作，
不能称为无法绕过的安全认证。

## 恢复原厂 ROM

向导下方的折叠入口可以恢复同一台机器的完整 Flash 主数据 `.bin`。文件大小必须与芯片主数据容量一致；逐块擦写并回读校验，成功后提供重启按钮。旧版 U-Boot 可以先使用电脑端工具诊断并调用其现有接口，见 [完整 ROM 恢复与诊断](stock-rom-recovery.md)。

## 签名与启动

上游发布的镜像用自签 RSA-4096 证书链签名（`sign-an758x-fip.sh`），这些
设备接受自签镜像。本仓库 `tools/build.sh` 默认生成自签密钥签名，做法与
上游一致；详见 docs/build.md 的"签名状态"。
